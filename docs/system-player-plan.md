# 菜单栏与 Touch Bar 播放器实现方案

状态：代码已实现，自动化回归与交叉构建已验证；macOS 原生显示和 Touch Bar 真机验收待完成。本文保留设计约束，实际落地与验证结果见第 13 节。

## 1. 目标与已确认决策

新增一个系统播放展示模块，提供三个功能：

1. macOS 菜单栏播放控制：上一首、播放/暂停、下一首和应用入口。
2. 菜单栏歌词：随播放切换当前句，长句横向滚动。
3. Touch Bar 播放控制与歌词：歌词前显示上一首、播放/暂停、下一首，与菜单栏使用同一份状态和动作。

菜单栏布局参考：

```text
[当前歌词……] [上一首] [播放/暂停] [下一首] [应用入口]
```

本次不包含喜欢按钮、喜欢状态同步及相关登录交互。不改动喜欢、账户和歌单业务。

刘海、菜单栏和 Touch Bar 的底层播放能力相同，展示方式不同。本次直接复用项目已经存在的播放核心，在它之上增加展示模块，不为了统一三个入口而迁移或重构刘海播放器。

命名约定：

- 独立包：`internal/systemplayer`。
- 应用接入对象：`systemPlayer`。
- 应用接入文件：`internal/app/system_player.go`。
- 设置分组：“菜单栏与 Touch Bar”，与“刘海播放器”并列。

## 2. 当前代码基础

| 现有位置 | 已有能力 | 本次使用方式 |
| --- | --- | --- |
| `internal/player/player.go` | 播放队列、播放暂停、切歌、进度、歌词数据、系统媒体控制、`Changed` 回调 | 继续作为播放状态的唯一来源 |
| `internal/lyrics/lyrics.go` | LRC/YRC 解析、翻译、逐字时间、`Index` 当前行定位 | 复用当前行定位，不增加歌词解析器 |
| `internal/app/tray.go` | 托盘显示、应用图标设置、打开窗口、设置、更新和退出菜单 | 协调 macOS 菜单栏所有权，复用菜单行为 |
| `internal/app/ui_notch.go` | 刘海播放器 UI 和交互 | 参考交互，保持现有实现 |
| `internal/app/notch_darwin.go` | `purego/objc` 原生桥接 | 沿用技术路线，不复制刘海窗口逻辑 |
| `internal/app/session.go` | `time.AfterFunc` 配合 `mygo.RunOnMain` 的无重绘调度 | 参考主线程调度方式 |
| `internal/app/settings.go`、`ui_settings.go` | 设置持久化、分组与应用 | 增加独立设置组 |

已检查当前锁定版本的 MyGo（`v0.7.1-0.20261027023711-da3657e7f86a`）：

- `Tray` 支持图标、标题、菜单、点击和屏幕位置。
- 没有公开托盘原生句柄或自定义内容视图，也没有现成的 Touch Bar 接口。
- `Window.NativeHandle()` 和 `RunOnMain()` 可用于受控的原生接入。
- 当前 macOS 后端支持通过 `Menu.Popup(nil)` 在鼠标位置显示菜单，可用于复用现有菜单，而不访问 MyGo 内部类型。

组合按钮和连续文字滚动使用原生控件实现。本次不修改、分叉或升级 MyGo 来增加接口；菜单弹出位置及交互仍需 macOS 实机验证。

## 3. 架构与依赖边界

```text
现有公共核心
  Player / lyrics / 应用操作
      │
      ├── 主窗口
      ├── 刘海播放器（现状）
      └── app.systemPlayer（本次新增的接入对象）
              │  State / Options / Actions
              ▼
          systemplayer.Player
              ├── 菜单栏原生视图
              └── Touch Bar 原生视图
```

依赖仅允许由 `app` 指向 `systemplayer`。展示包不导入 `app`、`player`、`lyrics` 或网易云 API，不读取设置文件，不发起网络请求，也不创建另一个播放器。

### 3.1 应用接入层

`internal/app/system_player.go` 负责：

- 从 `Player` 读取当前歌曲、播放意图、加载状态和歌词。
- 用现有 `lyrics.Index` 生成当前歌词展示结果。
- 绑定播放、切歌、打开主窗口和打开菜单的动作。
- 将持久化设置转换为展示配置。
- 管理唯一的歌词同步计时器。
- 将播放事件与生命周期接入展示包。

它是业务与展示之间的接入点，不引入新的业务状态源。

### 3.2 展示包

`internal/systemplayer` 负责：

- 原生控件的创建、布局、事件绑定和释放。
- 将一个状态快照更新到菜单栏及 Touch Bar。
- 文本测量、裁剪和横向滚动。
- 深浅色、辅助功能标签和原生容器可见性处理。
- 绑定主窗口的 Touch Bar，并在关闭时恢复其原有绑定。

两个视图共享内容与动作，但分别保存布局、滚动位置等视图状态。它们宽度不同，不能强行共用一个滚动偏移。

不新增事件总线、通用插件系统、Model/Controller 子包或面向未来的多端 Adapter 框架。

## 4. 最小接口设计

以下是接口形状，具体字段以实现所需为准，不为未实现功能预留字段。

```go
// State 是可由当前播放数据重建的展示快照。
type State struct {
    TrackID    int64
    HasTrack   bool
    Playing    bool
    Loading    bool
    CanToggle  bool
    CanSkip    bool
    LyricIndex int
    LyricText  string
}

type Options struct {
    MenuBarVisible  bool // 综合应用图标设置与功能开关后的有效配置
    MenuBarControls bool
    MenuBarLyrics   bool
    TouchBarLyrics  bool
}

type Actions struct {
    Previous func()
    Toggle   func()
    Next     func()
    Menu     func()
    TouchBarVisibilityChanged func(bool)
}

// Host 仅用于初始绑定，不传入 app 或 Player 对象。
type Host struct {
    WindowHandle uintptr
    Name         string
    Icon         []byte
}

func New(host Host, actions Actions) (*Player, error)
func (p *Player) Update(state State)
func (p *Player) Configure(options Options) (effective Options, err error)
func (p *Player) Close()
```

约束：

- 所有调用、状态读取及原生回调均在主线程执行，应用接入层负责保证。
- `State` 不包含播放器指针、播放队列或歌词全集。
- `CanToggle`、`CanSkip` 由接入层结合现有播放器行为计算，不在视图内推导队列逻辑；队列末尾等行为仍由 `Player` 决定。
- `Update` 对内容做差异更新，每次调用均检查原生可见性与动画。歌曲和歌词行身份变化时重置滚动；相同文本的不同歌词行也需要重置。标题回退直接通过 `LyricText` 传入，不额外传递未使用的标题或歌手字段。
- `New` 仅绑定宿主和回调，展示端统一通过 `Configure` 启用。`Configure` 分别应用两个展示端，返回实际生效的配置及错误。任一端初始化失败都不能关闭另一端；调用者即使收到错误，也使用返回的有效配置协调托盘和调度。
- `Close` 可重复调用；关闭后的更新及排队回调不再访问原生对象。
- 非 macOS 提供无副作用的空实现，不创建计时器或原生资源。

若实现验证发现需要调整接口，应保持上述单向依赖和职责分配，而不是增加通用管理层。

## 5. 菜单栏与原托盘的衔接

菜单栏区域采用一个 `NSStatusItem`，内部布局歌词、控制按钮和应用入口。保持稳定的 autosave 标识，验证用户拖动位置在重启后能够恢复。

菜单栏所有权由 `app/tray.go` 协调：

| 设置与状态 | macOS 菜单栏所有者 |
| --- | --- |
| 应用图标选择“仅程序坞” | 不显示菜单栏入口 |
| 允许菜单栏，但两个菜单栏功能均关闭 | 原有 MyGo 托盘 |
| 允许菜单栏，控制或歌词至少启用一个 | 新模块的组合菜单栏 |
| 只启用 Touch Bar | 原有托盘规则不变 |
| 新菜单栏初始化失败 | 记录错误并回退到原有托盘 |

要求：

- 新入口准备成功后再移交所有权；切换结束后始终只有一个应用图标。
- 关闭新功能后恢复原托盘；不因功能切换丢失打开窗口、设置和退出入口。
- 新入口左键及右键均通过 `Actions.Menu` 打开原应用菜单；主窗口从菜单里的“打开”进入。菜单在主窗口隐藏时也必须可用。
- 新模块菜单复用现有菜单构建逻辑，按用途排除喜欢项；旧托盘已有行为不在本次顺带修改。
- 不持有或猜测 MyGo 托盘的内部原生对象，不为弹出菜单再创建一个隐藏托盘。
- Windows/Linux 继续使用原有托盘逻辑。

菜单打开后的定位、焦点、深浅色和菜单跟踪期间的动画行为列为 macOS 验收项。

## 6. 歌词与播放状态同步

### 6.1 事件同步

在已有 `Player.Changed` 回调中追加接入模块的同步，保留会话保存与字幕同步。

补齐当前通知缺口：

- 切歌开始、旧歌词被清空之后。
- 当前歌曲的歌词异步加载完成之后。
- 单曲循环回到开头之后。

复用已有暂停、恢复、Seek、加载完成和播放失败通知。通知必须在相关字段更新完整后触发；过期歌曲的异步返回继续使用现有代次检查丢弃。

可以提取一个轻量的 `notifyChanged()`，由 `sync()` 及上述缺口调用。纯展示变化不必重新发布系统媒体信息，也不能在歌词计时器中触发 `Changed`，避免带动会话保存等额外工作。

### 6.2 播放进度同步

首版使用一个约 100ms 的可取消计时器，读取真实 `Player.Position()`，不累计本地时间估算播放进度。

运行条件：

- 至少一个有效展示端需要动态歌词。
- 播放器已经就绪、处于播放中且有可同步的歌词。
- 模块尚未关闭。

Touch Bar 单独启用且应用不在可展示它的前台状态时，停止无用采样；激活、窗口焦点或绑定变化时立即同步再决定是否恢复。菜单栏启用时，主窗口隐藏不能停止歌词同步。

Touch Bar 是否展示以歌词项 `NSTouchBarItem.isVisible` 为依据，同时检查应用激活及主窗口焦点。展示包观察 `visible` 的 KVO 变化，通过 `Actions.TouchBarVisibilityChanged` 通知应用接入层；切换功能键、Control Strip 或隐藏歌词项后停止采样，重新展示时立即同步。原生通知合并后延迟到主线程执行，避免在配置或解绑过程中重入，关闭模块后丢弃已排队的通知。

暂停、关闭所有歌词展示或退出时取消计时器。回调进入主线程后检查关闭标记与调度代次，防止取消前已排队的旧回调重新启动下一轮。

计时器通过 `mygo.RunOnMain` 执行同步，不调用会触发窗口重绘的 `a.post()`。主窗口、刘海播放器和菜单栏不互相驱动动画帧。

### 6.3 文本规则

| 场景 | 展示行为 |
| --- | --- |
| 无当前歌曲 | 收起歌词区域，保留应用入口；无可用操作时禁用相应按钮 |
| 歌曲或歌词加载中 | 显示歌名，不保留上一首歌词 |
| 没有歌词、获取失败或首句开始前 | 显示歌名 |
| 当前有歌词行 | 显示原文当前句，随 `lyrics.Index` 切换 |
| 暂停 | 保留当前句并停止横向动画 |
| Seek、切歌、循环 | 重新定位当前句，按行身份变化重置滚动 |
| 最后一句之后 | 保留末句直到切歌或停止 |

首版沿用 `lyrics.Index` 的当前行语义，不另做间奏检测、过滤署名、双语展示或逐字着色。现有歌词加载结果不能区分纯音乐与请求失败，因此统一使用歌名回退，不把所有空歌词都标成“纯音乐”。

播客首版同样使用现有歌词结果或标题回退，不新增本地转写字幕接入。

### 6.4 滚动规则

- 菜单栏歌词按实际文字宽度收缩，最长 120 点；长句在视口内滚动，短句归还多余空间。按钮宽度为 24 点，全功能布局最大约 228 点。
- 短句静止；长句开始时短暂停留，然后向左滚动，末尾停留后重复。
- 暂停时冻结，恢复时继续；换句重新开始。
- 使用实际文本排版宽度，正确处理中文、emoji 和组合字符，不按 UTF-8 字节截断。
- 仅在超宽、播放中且视图需要显示时运行动画；短句、隐藏、关闭和减少动态效果模式下停止连续动画。
- 两个容器可以共用小型滚动计算辅助函数，但不因此新建动画框架。
- 通过 `NSWorkspace.notificationCenter` 监听显示辅助选项变化，使关闭“减少动态效果”后即使没有歌词采样也能恢复动画。退出时移除监听并释放 block。原生计时器使用系统导出的 `kCFRunLoopCommonModes` 常量，不自行构造同名字符串。

## 7. Touch Bar 原生接入

使用公开的 `NSTouchBar`、`NSCustomTouchBarItem`，通过主窗口原生句柄安装内容。

- 当前歌词及标题回退前显示上一首、播放/暂停、下一首；按钮复用菜单栏的原生创建、状态更新与动作回调。
- 启用时保存原有绑定；关闭或退出时解除自身绑定并恢复原状态。
- 切换应用、窗口焦点和主窗口隐藏时遵循系统响应链，不强行占用其他应用的 Touch Bar。
- 不使用私有 API 实现全局常驻；“后台跨应用持续显示歌词”不属于本次承诺。
- 在无 Touch Bar 设备上安全退化，不影响菜单栏，也不能仅因类存在就宣称硬件支持。
- 不替换 MyGo 已有窗口 delegate；确有必要的辅助对象由展示包自身持有和释放。

## 8. 设置与生命周期

新增三个布尔设置，默认关闭：

```text
menuBarControls  菜单栏播放控制
menuBarLyrics    菜单栏歌词
touchBarLyrics   Touch Bar 歌词
```

设置面板独立成组“菜单栏与 Touch Bar”，仅在 macOS 显示。文字自动滚动不另设开关，首版不暴露字体、速度、宽度和动画模式等配置。

选择“仅程序坞”时，两个菜单栏设置保留用户偏好但不生效，设置页给出原因并禁用相关操作；Touch Bar 不受影响。与刘海播放器的开关互不覆盖，可以同时启用。

启动顺序：加载设置和创建播放器 → 创建主窗口 → 创建应用接入对象 → 应用配置与协调托盘 → 同步当前状态。播放器初始化期间的回调允许模块尚不存在，接入处必须判空；模块创建后主动同步一次补齐状态。

退出顺序：停止接入层计时器并使旧回调失效 → 停止原生动画 → 解除回调与 Touch Bar 绑定 → 移除菜单栏对象并释放资源。清理期间不触发“恢复旧托盘”。

Objective-C 对象、block、target 和观察者的所有权明确保存在展示包；Go 回调在原生对象存活期间保持有效，关闭后断开引用，避免悬空回调与重复释放。

## 10. 实施顺序

### 第一步：验证原生接入并建立模块

- 建立包边界、空实现和应用接入对象。
- 在 macOS 验证自定义 `NSStatusItem` 按钮交互、复用菜单以及 `NSTouchBar` 安装/解绑。
- 提前确认 MyGo 事件循环和原生回调可协同工作，不将平台可行性验证拖到最后。
- 新功能全部关闭时验证现有托盘和刘海行为不变。

### 第二步：菜单栏播放控制及设置

- 接入状态、动作、三个设置和托盘所有权切换。
- 补齐播放器必要通知，验证加载中切歌、暂停和播放失败的显示。
- 验证主窗口隐藏后控制仍可用，以及初始化失败可恢复原入口。

### 第三步：共享歌词同步与菜单栏滚动

- 实现状态投影、唯一计时器与差异更新。
- 实现原生滚动及暂停/隐藏停止规则。
- 验证切歌、Seek、循环、无歌词和旧异步结果处理。

### 第四步：Touch Bar 歌词与整体验收

- 将同一份状态接入 Touch Bar，不增加第二个歌词计时器。
- 验证前后台切换、主窗口隐藏、无硬件退化和反复开关。
- 完成原生资源清理、跨平台回归及视觉验收。

## 11. 测试与验收标准

遵循仓库 `AGENTS.md`：只测试会影响行为的逻辑，不测试设置文案、默认值或控件排列；不依赖真实墙上时钟。

自动化重点：
